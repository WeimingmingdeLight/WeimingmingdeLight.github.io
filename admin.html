先填一次你的 GitHub 令牌

这个页面就是本站的发布后台：上传新文章、更换封面、改简介。它需要你的授权才能写回仓库。 令牌只保存在这台设备的这个浏览器里（localStorage），不会写进网页、不会写进仓库、不会发给任何第三方； 页面上的所有请求都直接发往 api.github.com。

怎么建令牌（只做一次）：GitHub → 右上头像 → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token。
· Repository access：Only select repositories → 选 WeimingmingdeLight.github.io
· Permissions → Repository permissions → Contents: Read and write（其余全不用给）
· 有效期按你习惯（建议 90 天）；过期了就回来换一个。

公用电脑上别留令牌：用完点右上角「忘记令牌」。令牌泄露的后果是别人能改这个仓库的**内容**（改不了仓库设置）， 发现不对就去 GitHub 把那个令牌 Revoke 掉。
粘贴后点「连接并验证」。验证只读你的用户名与该仓库权限。

    自检：站内渲染 == 仓库现状？

    用仓库当前的内容，在这个浏览器里重跑一遍全部页面渲染，再逐个文件与仓库里的 blob 比对。 正常结果是「0 处差异」—— 那说明网页端和本地构建脚本产出完全一致。 这个过程只读不写，随时可以点。

    它做了什么、没做什么

    • 做了什么：把你的改动渲染成整站页面，用你自己的令牌一次性提交到仓库（一个提交），GitHub Pages 大约一分钟后更新。
    • 渲染在哪：就在这个浏览器里，用的是和本地构建脚本同一个文件（assets/js/render-core.js，由本地构建时逐字节复制）。所以网页上发的和本地发的产物是一样的。
    • 没做什么：没有后端、没有数据库、没有第三方服务；页面本身不含任何密钥，别人打开这个地址也只会看到一个令牌输入框。
    • 素材规矩：D 盘素材库里的文稿，由我取用时每次都会先问你；你自己在这里粘贴/上传的内容，是你自己的动作，不用再批一次。xin-chun（【歆春】）永久排除，不要加回来。
    • 删文章：这里不提供删除（删除要连带清掉封面、索引与讨论串，属于危险操作）。要下架告诉我，我用 retire_post.mjs 走完整流程。
